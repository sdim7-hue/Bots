# 🧪 QA-PROTOCOL — обязательный протокол приёмки FE-деливераблов

> **Канонический источник.** Применяется к ЛЮБОМУ продукту с UI (не только S3). Роли ссылаются сюда; мандатные гейты — `R-DC-20…22` в `DIGITAL-COMPANY.md §8`. Орк-байндинг — `CRITICAL-RULES.md`.
>
> **Происхождение:** S3-Мосводосток, 30.06.2026 — «demo-ready» объявлялось дважды преждевременно; баги входа / дропдаунов / прогресса загрузки / вечного спиннера версий / операторского авто-логина поймал лично владелец при ручном использовании. Разбор → этот протокол.

## Принцип
«Сделано» = то, что **ВИДИТ и может СДЕЛАТЬ пользователь в реальном браузере**. «API ответил 200» / «консоль чистая» / «объект в бакете» — НЕ засчитывается как «работает». Правило живёт в чек-листе / типе-задачи, а не в голове: вшитое — исполняется; «надо бы проверить как пользователь» — нет.

## Рамка ответственности
Провал QA — это провал **SCOPE брифов и определения гейта** (зоны Архитектора + Диспетчера), НЕ execution тестировщика. Тестировщик отрабатывает свои брифы корректно. Поэтому правила бьют в протокол, а не в усердие человека.

## 11 правил

### Тестировщик (Барбара) — execution
1. **Реальный браузер как пользователь, не API.** Каждый экран и действие — мышью/клавиатурой под реальным логином (.env). «API 200» не засчитывается; засчитывается видимый результат + **скриншот каждого экрана и результата** (`/tmp/uxsweep/` → durable в `acceptance-proofs/`).
2. **Оба портала, полный auth-loop через UI** (вход→действия→выход на каждом). Сессию НЕ инжектить готовой cookie — иначе пропустишь отсутствие экрана входа (как операторский авто-логин). Нет UI-входа = BLOCKER, не «потом».
3. **Проверять результат данных, не факт открытия.** Каждый async-экран резолвится в **данные / пусто / ошибку — НИКОГДА вечный спиннер**. «Объект в бакете» (API) ≠ «строка показала готово» (UI); «экран открылся» ≠ «версии пришли».
6. **Тест на реальном деплое через домен/прокси, не localhost/dev-сборку.** Сверять полный байт-размер ключевых ассетов через прокси + что served-версия == исправленная (корень бага «обрезанный `alpine.min.js`» → мёртвые дропдауны; класс «container ≠ served»).
7. **Edge/негатив, не только happy-path.** Клиент на operator-URL (должен отказ/редирект), пустой бакет (загрузка в корень + создание папки), большой файл (прогресс реально рендерится?), logout→повторный вход — каждое со скриншотом.

### Аналитик (Клейтон) — холистика + визуал
4. **Визуальный просмотр скриншотов ГЛАЗАМИ** (аналитик + оркестратор), не только assert-зелёный: заголовок = раздел (не имя клиента), прогресс/«готово» у загрузок, нет заглушечных имён/чисел, дропдауны открываются. Pixel/AA-харнес дополняет, но не заменяет просмотр.
5. **Холистический проход «всё разом против роадмапа»** — отдельный пасс перед demo-ready: каждая заявленная фича → **OK / PARTIAL / BROKEN / MISSING + пруф-скрин**. Пер-флоу-зелёные по отдельности ≠ покрыто в сумме.

### Диспетчер (Маргарет) — scope / брифы
8. **Бриф тестировщику = встроенный explicit scope-checklist**, не интерпретация исполнителя.
9. **Real-browser gate = явный тип задачи**, не сноска (binding в задачах диспетчера).
11. **Калибровка cron-монитора** (парсинг-баг + отличать штатный HOLD от реальной тревоги).

### Архитектор (Декстер) — гейт + классы
9. (общая) binding real-browser gate в стадии перед demo-ready.
10. **Class-of-error tracking — стандартный шаг ретроспективы** (каждый баг → класс ошибки, накопление в memory команды).

## Жёсткое определение «demo-ready» (keystone)
НЕЛЬЗЯ объявлять, пока ОДНОВРЕМЕННО не зелёные:
- браузерный проход **обоих** порталов (вход→действия→выход), скриншоты сняты;
- скриншоты **просмотрены глазами** (аналитик + оркестратор);
- **роадмап-матрица** OK по всем заявленным фичам.

Владелец гейта — **Архитектор**. **Оркестратор (claude-ilya) НЕ передаёт «demo-ready» Илье без собственной браузер+скрин-верификации.**
