# Журнал решений (ADR)

Краткие архитектурные решения проекта Bots. Новое — сверху или со следующим номером.

## ADR-001 — Источник правды задач: GitHub Issues (2026-05-30)

**Решение:** задачи ведём как GitHub Issues с метками статуса, а не в отдельной БД/файле.
**Почему:** не зависит от ОС (живёт на GitHub), доступно с любого ПК, переживает переезд
на Ubuntu и многомашинность. Человек уже использует Issues (проект map).
**Следствие:** оркестратор работает поверх GitHub API; локальная SQLite — только кэш/состояние.

## ADR-002 — OS-агностичное ядро + адаптер запуска (2026-05-30)

**Решение:** ядро (оркестратор + работа с Issues/Actions) пишем кроссплатформенно на Python;
запуск ботов выносим в заменяемый адаптер.
**Почему:** запланирован плавный переход Windows → Ubuntu (dual-boot → несколько ПК).
Вкладываться в Windows-специфику нельзя — это выкинутая работа.
**Следствие:** на Ubuntu добавляется tmux-адаптер и автономный цикл Ильи без переписывания ядра.

## ADR-003 — Роли N+1, оркестратор не пишет код (2026-05-30)

**Решение:** конфигурация «N кодеров + Ultra Reviewer + Диспетчер». Claude-оркестратор
код не пишет — брифы и контроль.
**Почему:** доказанная у Ильи модель — выше качество (узкий scope ботов, ревьюер ловит
пропущенное), дешевле по токенам, даёт параллелизм.
**Следствие:** на старте минимальный состав (1 кодер + ревьюер + диспетчер), масштабирование позже.

## ADR-004 — Стек: Python 3.11 + SQLite, без тяжёлой инфраструктуры (2026-05-30)

**Решение:** Python 3.11 (уже в среде), SQLite для локального состояния. Redis/Docker/
сторонние оркестраторы не тащим на старте.
**Почему:** одна машина, простота, портируемость. Добавим инфраструктуру при реальной нужде.
