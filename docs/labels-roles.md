# Метки ролей исполнителя

> Дополнение к [labels.md](labels.md). Метка `role:*` выбирает роль исполнителя
> задачи; `status:*` описывает фазу жизненного цикла. У задачи ровно одна `role:*`.

## Роль — кто исполняет (всегда ровно одна активна)

| Метка | Смысл |
|---|---|
| `role:coder` | пишет код по брифу |
| `role:reviewer` | ревьюит результат кодера |
| `role:tester` | проверяет поведение (сборка/тесты/прогон) |

## Взаимодействие с циклом `status:*`

`role:*` не меняется в ходе цикла — она маршрутизирует задачу к нужному боту на
каждой фазе `status:*`:

```
queued → in-progress → review → tested → done
 coder      coder      reviewer  tester   (человек)
```

- `queued` + `role:coder` — задачу берёт кодер;
- `review` — эстафета к `role:reviewer`;
- `tested` — к `role:tester`;
- `done` ставит только человек (см. CLAUDE.md).

## Атомарный захват задачи

Захват обязан быть атомарным: назначь себя assignee и **убедись, что assignee был
пуст** до этого. Непустой assignee = задачу уже взяли → не пиши вслепую, эскалируй.
После захвата — метку `status:queued → status:in-progress`.
