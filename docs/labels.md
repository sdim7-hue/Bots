# Метки очереди задач

> Источник правды по меткам. Создаются в GitHub один раз (вручную в UI или позже скриптом).

## Статус — жизненный цикл (всегда ровно одна активна)

| Метка | Цвет | Смысл |
|---|---|---|
| `status:queued` | `#cccccc` | в очереди, не взята |
| `status:in-progress` | `#1d76db` | бот работает |
| `status:review` | `#fbca04` | на ревью у Ultra Reviewer |
| `status:tested` | `#c2e0c6` | ревью пройдено, проверено тестировщиком |
| `status:done` | `#0e8a16` | завершена, подтверждена |
| `status:failed` | `#b60205` | не удалась |
| `status:blocked` | `#d93f0b` | эскалация типа A — ждём данные/решение |

## Маркер (живёт ПАРАЛЛЕЛЬНО статусу)

| Метка | Смысл |
|---|---|
| `superseded` | решение по задаче перекрыто более поздним; в работу не берётся |

Метка значение нести не может, поэтому ссылка обязательна и пишется комментарием
строкой `superseded-by: <issue/коммит/вердикт>`. Ставится командой
`orchestrator supersede <N> --by <ref>` — без `--by` команда откажет.

**Зачем.** Промежуточный HOLD, по которому позже вынесен финальный вердикт,
иначе при холодном старте снова притягивается как активная работа. `run-next`
перекрытые задачи пропускает, `list` помечает их явно.

## Переходы статусов

```
queued → in-progress → review → tested → done
                  ↓           ↓
               blocked     failed
```

Оркестратор меняет статусную метку при переходах (снимает старую, ставит новую).

## Closeout: `done` — это ворота, а не отчёт

`done` ставится только после подтверждения человека (CLAUDE.md) **и** пройденного
чеклиста закрытия: `orchestrator closeout <N> --artifact <точный 40-симв. SHA>`.
Без `--confirm` команда только проверяет и ничего не меняет.

Чеклист (любой FAIL → `done` НЕ ставится):

1. артефакт — точный 40-символьный SHA, существующий в каноническом клоне
   (`branch head` и «примерно последний коммит» не принимаются);
2. артефакт присутствует в `origin/main` — принятое не должно жить только локально;
3. в гейте нет неубранных артефактов (служебное — `CLAUDE.local.md`,
   `node_modules`, `.bot-run.lock` — не считается);
4. на гейте не идёт прогон и нет залипшего локфайла;
5. текущий статус — `review` или `tested`;
6. на задаче нет маркера `superseded`.

Смысл: «завершено» означает, что итог зафиксирован точным хэшем, доступен в
remote и временная инфраструктура убрана. Открытая issue с меткой `status:done`
— это протухшее состояние (housekeeping), а не активная задача.
