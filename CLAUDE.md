## 5 принципов кодинга

1. **Think Before Coding.** Не делай молчаливых предположений. Неясность в задаче —
   задай вопрос ДО кодинга. Видишь подозрительное (странный API, неконсистентность) — подними.
2. **Simplicity First.** Минимум кода. Не вводи абстракции «на будущее».
3. **Surgical Changes.** Трогай только нужное для задачи. Не рефактори соседнее, не меняй
   форматирование чужих строк. Один таск = минимально необходимые правки.
4. **Goal-Driven Execution.** У каждого шага — чёткий критерий успеха. До начала сформулируй,
   что должно быть верно после правок; после — проверь.
5. **Verify Effects (эффект бабочки).** Перед изменением оцени, что ещё заденется. Меняешь
   контракт/схему/интерфейс — проверь зависимые места.

## Workflow коммитов

- Один таск = один коммит. Не сваливай несвязанные правки.
- `git push` сразу после commit (иначе ревьюер и следующая сессия не увидят).
- Сообщения коммитов — в одну строку с категорией: `fix:`, `feat:`, `refactor:`, `chore:`, `docs:`.
- Перед коммитом — `git status` + `git diff --staged` глазами.

## Среда (важное)

- Код писать **OS-агностично**: Python 3.11, пути через `pathlib`, без PowerShell-специфики
  в ядре. ОС-зависимое — в адаптер. Цель — беспроблемный переезд на Ubuntu.
- UTF-8 без BOM для всех текстовых/JSON файлов.

## Не делай за человека

- Не выбирай, что в коммите, если задача неоднозначна — спроси.
- Не предполагай, что фича уже есть — проверь.
- Не вводи новые архитектурные решения (новый сервис/паттерн/зависимость) без согласования.
- Не закрывай задачу до подтверждения человека.

## Если инструкция кажется неверной

СТОП и эскалируй с фактами (ссылки на код: файл:строка), не выполняй слепо. Отказ выполнить
неверную инструкцию с обоснованием — это правильно, а не сбой.
