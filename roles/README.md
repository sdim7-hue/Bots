# Роль-промпты (адаптация системы Ильи под Bots)

Источник: дамп Digital Company Ильи (2026-07-03), оригиналы — `docs/reference-ilya/`.
Слой ролей = один Claude Code с разными промптами (ARCH-MULTIAGENT). Оркестратор
запускает роль в изолированном чекауте (механический гейт, без origin у бота).

## Ключевые отличия от системы Ильи (НЕ переносить обратно!)
- **Координация ТОЛЬКО через доску Forgejo**: issues + метки `status:*` + комментарии.
  Никаких tmux-релеев, прямых бот→бот, диспетчера-курьера. Прямые вызовы = паутина.
- **Цикл меток:** `status:queued` → `in-progress` → `review` → `tested` → `done`.
  Роль-адресат — метка `role:*`. Захват задачи атомарный: assignee + проверка,
  что никто не взял (предохранитель против гонки).
- **Предохранители обязательны:** лимит итераций на задачу, бюджет `cost_usd`,
  надзорный режим — подтверждение человека перед merge и платными прогонами.
- **Узловая автономность:** роль не предполагает конкретный узел/ОС; всё состояние —
  в репо и на доске.

## Что взято у Ильи как есть (проверено практикой)
- Разделение «роль ничего не делает вне своей зоны» + списки «НИКОГДА».
- Reviewer = первая линия security (semgrep/gitleaks, эксплойт = CRITICAL всегда).
- QA-PROTOCOL: «сделано = видит пользователь в реальном браузере», не «API 200».
- Брифы = цель+контекст+критерий, не пошаговая инструкция.
- P-NO-SELF-EDIT: роль не правит свой промпт, только сигналит ретроспективой.
- Внутренние брифы/отчёты — EN (~1.7× экономия токенов); эскалации человеку — RU.
- «Запрос инструмента ДО и ВО ВРЕМЯ задачи, не после».
- Retrospective-блок при DONE: ✅/⚠️/💡 (комментарий в issue).

## Порядок внедрения — по плану ARCH-MULTIAGENT (1→5)
1. coder + reviewer (текущий шаг) · 2. предохранители · 3. tester ·
4. RAG → writer/библиотекарь · 5. остальные роли. Не поднимать всех сразу.
