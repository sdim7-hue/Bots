# Skill: Local RAG — семантический поиск по vault

Локальный RAG поверх Obsidian-vault (`~/Obsidian/Claude-Vault/`): hybrid retrieval (BM25 + vector + RRF) по ~8000 чанкам. Запускается локально (Ollama `bge-m3` + SQLite). Закрыт в Phase 4 (2026-05-30), end-to-end проверен Ильёй.

## Как вызвать (CLI, через bash)

```bash
cd ~/personal-local-rag
# поиск
python3 -m code.cli search "<запрос>" --top-k 5 --mode hybrid --format json
# контекст вокруг найденного чанка (соседи по файлу)
python3 -m code.cli context <chunk_id> --neighbors 1 --format json
```

- `--format json` для ботов (парсишь результат), `text` для человекочитаемого вывода.
- `--mode`: `hybrid` (дефолт, лучший) | `vector` (только семантика) | `bm25` (только точные слова/термины/ID).
- `--top-k N` — сколько чанков (дефолт 5).
- Каждый chunk: `chunk_id, path, breadcrumb, text, similarity, bm25_rank, rrf_score, mode`.
- `context <chunk_id>` берёт `chunk_id` из результата `search` → возвращает `{path, center, context:[...]}` (центральный чанк + соседи). Используй чтобы расширить обрезанный фрагмент.
- БД read-only — поиск ничего не меняет. Если не в `~/personal-local-rag/` — добавь `PYTHONPATH=~/personal-local-rag`; путь к индексу зашит дефолтом, работает из любой cwd.

## ⭐ Middleware pattern — ГЛАВНЫЙ урок Phase 4 (применяй всегда)

**Raw retrieval = ~71% (FLOOR). Ты (Claude) — middleware между собой и RAG, и поднимаешь это до CEILING.** Не верь top-1 одного запроса. Делай так:

1. **2-4 параллельные формулировки** одного вопроса: синоним, перефраз, точный термин, транслитерация. Пример: вопрос «AI нода» → запусти `search` на: `"AI-NODE"`, `"AI нода GPU аналитика"`, `"ai node spec"`, `"GPU сервер LLM"`.
2. **Собери top-k от каждой**, **dedup по `path`/`chunk_id`**, синтезируй ответ из объединённого набора — не из одного хита.
3. Если фрагмент обрезан или нужен контекст вокруг — `context <chunk_id>`.
4. Для точных терминов/ID/имён файлов/аббревиатур (`ADR-002`, `nvr-v0.3.1`, `mTLS`) — `--mode bm25` ловит лучше; для смысловых вопросов — `hybrid`.

Почему: один запрос промахивается на token-mismatch (транслитерация, дефисы, синонимы). Несколько формулировок + синтез — это и есть «Claude поверх RAG». Это не опционально, это способ использования.

## Когда ИСПОЛЬЗОВАТЬ

- Нужен исторический/проектный контекст которого нет в текущем диалоге: «что мы решали про X», «был ли уже эпик Y», «какой принцип про Z».
- Onboarding в тему: найти `modules/<тема>.md`, связанные `lessons/`, `decisions/`, ADR.
- Проверка «делали ли мы уже это» перед реализацией (анти-дубль).
- Найти файл который документирует подсистему (когда не знаешь точный путь).

## Когда НЕ использовать

- Ответ уже есть в текущем контексте/диалоге — не дублируй поиском.
- Тривиальные факты, не требующие vault.
- Данные которых нет в vault: live-состояние серверов → SSH; код в репозитории → `grep`/`read` напрямую (быстрее RAG).
- Секреты: в индексе их НЕТ (`*.local.md` исключены); значения паролей/токенов — на Яндекс.Диске, не в RAG.

## Под ролью

- **Coder** — найти прежние решения/паттерны/lessons перед написанием кода; анти-дубль.
- **Writer** — найти существующие доки/модули чтобы не дублировать, проставить cross-ref.
- **Reviewer** — найти связанные lessons, принципы (P-rules), прежние review-паттерны.
- **Tester** — найти прежние тест-сценарии и regression-кейсы (TS-* lessons).
- **Architect** — butterfly-анализ: какие модули связаны с темой; прежние ADR/decisions.
- **DevOps / Dispatcher** — setup-процедуры, инфра-доки, история координации (ситуативно).
